# Avatar Assets Guide

This project is the preview/export surface for the OneWorks avatar visual system.

- `../../packages/avatar/src/avatar.ts`: shared pure SVG generator, pixel glyph definitions, palettes, and presets.
- `src/App.tsx`: standalone preview/export surface.
- `src/App.scss`: page layout and interaction styling.
- `.github/workflows/deploy-avatar.yml`: GitHub Pages deployment owned by the `oneworks-ai/avatar` repository.

The interactive preview uses geometric SVG face primitives instead of the legacy pixel emoticon glyphs. Its baseline face is a pair of rounded-rectangle eyes; keep new face work vector-native and do not replace it with web fonts, canvas text, or raster images. The legacy pixel avatar generator remains owned by `../../packages/avatar` until its export contract is intentionally replaced.

The interactive preview uses a sphere as the default avatar head surface. Keep geometric face primitives attached to the selected body's curved surface; any alternate head surface must be an explicit opt-in rather than replacing the spherical default. Tessellate every face boundary, including the nominally straight sides of rounded rectangles, before projecting it onto the body surface; projecting only edge endpoints leaves straight screen-space chords that visibly detach from the curved body. Face marks read as flush surface decals rather than recessed holes: render the foreground at full opacity and attenuate optional screen-space face shadows by the projected surface normal so they disappear near tangent angles instead of separating from the mark. The Build panel owns face geometry: eyes support rounded-rectangle and ellipse types plus width, height, gap, a shared rotation, independent additive left / right tilts, and rounded-rectangle corner ratio; the optional nose supports inverted-triangle, ellipse, and rounded types plus size, vertical position, and rotation; the optional mouth is a curved geometric band controlled primarily by smile / flat / frown curvature plus width, thickness, and vertical position. Parameters persist in the URL and transition through stable interpolated geometry instead of jumping between values. Independent eye tilts are part of complete face state and must be captured and interpolated by animation keyframes; older saved animations that predate them resolve both offsets to zero. The Default face action is a compact 48px icon button that restores the complete baseline configuration rather than acting as a decorative selected card. Pointer drag updates the pose and leaves it at the released angle; do not automatically spring or reset the avatar back to center. Rotation is continuous on both axes: never clamp the pose, and occlude the geometric face while it travels behind the body.

The interactive sphere's light source defaults to off. When enabled it controls surface shading, with independently adjustable direction and angle; it must not be represented by permanently visible mesh lines. The optional face shadow applies consistently to every enabled geometric face part and exposes direction, distance, softness, and opacity in the Effects panel; keep those values URL-persistent. The surface grid appears only while a pointer drag is active and disappears on release. Move mode translates the complete avatar (body and face together), allows at least half of the object to travel past the visible boundary, and scales that same complete object through macOS trackpad pinch gestures or mouse-wheel input. Released position and size persist without springing back. Rotate mode must transform the body and geometric face through the same 3D pose so the expression remains attached instead of sliding in screen space. The selected primary drag mode is exposed as compact icon-only controls in the stage's bottom-left corner. Right-button or macOS auxiliary-click drag, plus double-click-and-hold drag, temporarily moves the whole avatar without changing that selected primary mode or opening the context menu. Persist yaw, pitch, whole-object X/Y position, scale, and the active Rotate / Move mode in the URL so a shared or refreshed link restores the complete composition. A link without view-state parameters uses the module-owned baseline scale, sized so the rounded body occupies approximately 80% of the canvas instead of falling back to browser numeric zero semantics.

The stage defaults to an unframed editing surface. Its top-left corner owns only the persistent camera action. The top-right action row owns save or camera export, GitHub, theme, and controls-sidebar actions in that order, with the sidebar collapse / expand action always at the far-right edge. The theme follows the system color scheme until the user explicitly switches it for the current page. Collapsing controls hides only the right sidebar and lets the stage fill the available workspace; it must not break the full-width animation panel. The camera action toggles camera mode without changing the avatar pose, position, scale, or face parameters. Only camera mode shows the bounded backdrop and replaces save with the export toolbar in the top-right action row; its backdrop color and square, rounded-square, or circular frame shape are configured in the Style panel and persist in the URL. The editing surface must allow rotated, scaled, or translated geometry to render beyond the nominal SVG viewport without clipping; camera mode alone owns clipping to the captured frame. Keep every camera frame shape at the same dimensions as the editing canvas and vertically center that canvas using symmetric stage padding; bottom interaction actions are absolute overlays and must not reserve extra layout space that pushes the avatar upward. Entering or leaving camera mode, changing the frame shape, or opening Animation must never shift the avatar geometry.

The stage's top-right save action captures a raster thumbnail of the current interactive SVG and stores the complete URL-backed avatar configuration as a local saved preset. The Build panel owns the saved-preset history at its top; each item is a 48px avatar thumbnail without a card surface, timestamp, or metadata chrome, its hit area and selected border follow that preset's own square, rounded, or circular camera-frame geometry, and selection is communicated only by that border. Selecting a thumbnail restores the complete body, face, view, palette, camera, lighting, shadow, interaction, and export state in one action. Keep saved presets browser-local, capped to a compact horizontal history, and resilient to malformed or obsolete local data. Saving or selecting a preset must not introduce a second configuration source: restored values continue through the normal state and URL synchronization path.

The stage's bottom-right Animation action opens a bottom timeline panel that spans the complete workspace beneath both the avatar stage and the controls sidebar; it must not be positioned inside or sized from the stage column alone. The panel separates creation and playback into explicit icon-labeled Create and Playback tabs without repeating an additional Animation title beside those tabs. The header keeps those tabs on the left and the global play / stop plus Create-only save icon actions pinned to the far right; do not duplicate those actions inside the settings card. On desktop, the panel's top edge is a height-resize boundary; its Playback library wraps into additional rows and scrolls vertically rather than creating a horizontal strip. Keep preview tiles at a stable size, distribute each row's remaining gap between items, and align the first and last tile to the content edges instead of leaving a residual empty block on the right. A keyframe records only whole-object X/Y position, yaw/pitch orientation, and the complete geometric face expression; it also captures a 48px transparent raster avatar thumbnail without the camera background or camera-frame crop. Keyframe selection uses one fixed rounded border independent of the configured camera frame. The thumbnail is display metadata and must not become animation state. Each draft keyframe has an explicit delete action. Playback interpolates numeric transform and face values across keyframes while keeping discrete face types stable until their transition point. At every new playback start, re-anchor the complete timeline to the avatar's current X/Y position and yaw/pitch orientation by applying the first-frame transform delta to every frame; preserve movement internal to the animation instead of snapping back to the coordinates that were active when the animation was selected or recorded. Only an animation that explicitly opts into a future locked-transform contract may bypass this re-anchoring. Built-in frames may provide normalized non-uniform timing offsets so long holds, quick blinks, rebounds, and return poses do not collapse into equal-duration steps; apply easing within each frame segment instead of warping the entire timeline. The Playback tab is one animation library: do not separate built-in presets and locally saved animations into different labeled groups or card treatments. Every library item directly renders a live avatar using the current body, palette, lighting, and shadow appearance; do not show a duration or separate text area, and overlay only the animation name at the preview's bottom-right. Selecting any library item stays in Playback, replaces the shared editor draft after confirmation only when that existing draft contains user-authored or saved content, opens the right-side animation tool panel with the selected frames, and immediately loops the animation. The selected source being built-in or saved does not affect replacement confirmation. The right-side tool panel owns selected-frame previews, total duration, once / loop behavior, and easing. The built-in library covers subtle idle, blink, listening, nod, thinking, searching, working, happy, curious, surprised, bored, sad, laughing, playful, excited, and celebrate behaviors; each resolves relative to the current view and face, then loads into the same editable timeline without changing body shape, palette, camera, lighting, or shadow. Preset durations must preserve readable holds and transitions; avoid globally compressed playback that makes every expression feel abrupt. Every built-in or selected saved frame must be rendered offscreen through the same interactive avatar and transparent screenshot pipeline and backfilled with its own distinct thumbnail; do not leave frames as numbered fallbacks, duplicate one current-stage image across the sequence, or reuse camera-mode screenshots. Saved animations remain browser-local and can be loaded back into the shared timeline. Manual transform or face editing stops active playback. Do not introduce model-part binding or skeletal control until a concrete model contract exists.

The controls sidebar and full-width Animation panel are desktop work surfaces, not opaque page partitions. Render both as translucent frosted-glass panels with a thin boundary, backdrop blur, and sufficient text/control contrast in both themes. The controls sidebar exposes a draggable left boundary for width adjustment, while the Animation panel exposes a draggable top boundary for height adjustment; both handles support keyboard arrows and reset on double click. Keep these resize affordances hidden in the single-column narrow-screen layout.

The controls sidebar uses a four-way segmented button tab group for Build, Body, Style, and Effects. Keep the icons and accessible tab semantics, but use bounded button surfaces and a filled selected state instead of underline-only navigation.

The app repository triggers this Pages deployment only when `assets/avatar/**` or `packages/avatar/**` changes. Do not broaden the trigger to all `packages/**`.
