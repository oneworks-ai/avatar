# Avatar Assets Guide

This project is the preview/export surface for the OneWorks avatar visual system.

- `../../packages/avatar/src/avatar.ts`: shared pure SVG generator, pixel glyph definitions, palettes, and presets.
- `src/App.tsx`: standalone preview/export surface.
- `src/App.scss`: page layout and interaction styling.
- `.github/workflows/deploy-avatar.yml`: GitHub Pages deployment owned by the `oneworks-ai/avatar` repository.

The interactive preview uses geometric SVG face primitives instead of the legacy pixel emoticon glyphs. Its baseline face is a pair of rounded-rectangle eyes; keep new face work vector-native and do not replace it with web fonts, canvas text, or raster images. The legacy pixel avatar generator remains owned by `../../packages/avatar` for its package API, while this editor's Copy SVG and Download SVG actions serialize the current interactive SVG so body, pose, face, lighting, shadow, and outline appearance are preserved.

The interactive preview uses a sphere as the default avatar head surface. Keep geometric face primitives attached to the selected body's curved surface; any alternate head surface must be an explicit opt-in rather than replacing the spherical default. Tessellate every face boundary, including the nominally straight sides of rounded rectangles, before projecting it onto the body surface; projecting only edge endpoints leaves straight screen-space chords that visibly detach from the curved body. Face marks read as flush surface decals rather than recessed holes: render the foreground at full opacity and attenuate optional screen-space face shadows by the projected surface normal so they disappear near tangent angles instead of separating from the mark. The Build panel owns face geometry: eyes support rounded-rectangle and ellipse types plus width, height, gap, a shared rotation, independent additive left / right tilts, and rounded-rectangle corner ratio; the optional nose supports inverted-triangle, ellipse, and rounded types plus size, vertical position, and rotation; the optional mouth is a curved geometric band controlled primarily by smile / flat / frown curvature plus width, thickness, and vertical position. Parameters persist in the URL and transition through stable interpolated geometry instead of jumping between values. Independent eye tilts are part of complete face state and must be captured and interpolated by animation keyframes; older saved animations that predate them resolve both offsets to zero. The Default face action is a compact 48px icon button that restores the complete baseline configuration rather than acting as a decorative selected card. Pointer drag updates the pose and leaves it at the released angle; do not automatically spring or reset the avatar back to center. Rotation is continuous on both axes: never clamp the pose, and occlude the geometric face while it travels behind the body.

The interactive sphere's light source defaults to off. When enabled it controls surface shading, with independently adjustable direction, angle, source distance, and surface-grid density. At the Near endpoint, dark-facing cells use a deliberately strong maximum contrast; increasing distance attenuates both highlight and shadow contrast until the surface becomes unshaded. Links without a distance parameter retain full-strength lighting. Grid density ranges from 25% through 400%, defaults to the original 14-by-28 tessellation at 100%, and changes only the shaded and drag-grid cells—not the high-resolution silhouette. Keep every light and density parameter URL-persistent and apply it consistently to stage, animation previews, and captured thumbnails. The light must not be represented by permanently visible mesh lines. The optional face shadow applies consistently to every enabled geometric face part and exposes direction, distance, softness, and opacity in the Effects panel; keep those values URL-persistent. Effects also owns an optional geometric avatar outline with color, width, and opacity controls. Render it from the same projected body path as the surface, replace the subtle default surface-edge highlight while it is enabled so no second line bisects the custom stroke, and persist its complete state in the URL and saved presets. The surface grid appears only while a pointer drag is active and disappears on release. Move mode translates the complete avatar (body and face together), allows at least half of the object to travel past the visible boundary, and scales that same complete object through macOS trackpad pinch gestures or mouse-wheel input. Released position and size persist without springing back. Rotate mode must transform the body and geometric face through the same 3D pose so the expression remains attached instead of sliding in screen space. The selected primary drag mode is exposed as compact icon-only controls in the stage's bottom-left corner. Right-button or macOS auxiliary-click drag, plus double-click-and-hold drag, temporarily moves the whole avatar without changing that selected primary mode or opening the context menu. Persist yaw, pitch, whole-object X/Y position, scale, and the active Rotate / Move mode in the URL so a shared or refreshed link restores the complete composition. A link without view-state parameters uses the module-owned baseline scale, sized so the rounded body occupies approximately 80% of the canvas instead of falling back to browser numeric zero semantics.

The global header ends with a language control. It opens an accessible single-choice language dialog, persists the chosen locale locally, updates the document language, and applies translations across the controls and animation UI. Keep English as a complete fallback for untranslated or user-authored content, and show language names in their native form so the chooser remains usable in either locale.

The stage defaults to an unframed editing surface. Its top-left corner owns only the persistent camera action while the stage is at least half the viewport width; below that measured width, move the camera action into the open sidebar's header actions, move the non-camera save action immediately to its left, and return both actions to the stage whenever the sidebar is collapsed. The top-right action row otherwise owns save or camera export. Camera export is one square trigger that opens a three-row menu: the first non-action row contains the usable size selector with a consistently padded custom chevron, followed by icon-labeled Copy SVG and Download SVG actions. When the controls sidebar is closed, that row additionally owns GitHub, theme, and the sidebar-expand action in that order. When the sidebar is open, its collapse action moves to the left of the settings tabs while GitHub and theme move to the tabs' right, leaving no duplicate sidebar or global actions on the stage. Those outer actions are square icon buttons, while the four middle settings tabs divide and fill all remaining horizontal space. The settings tabs use the same padded outer group and inset rounded selected state as the stage's mouse-drag selector. Face-part and background-style selectors use the same padded segmented-control treatment as the stage's mouse-drag selector and pair every text label with its corresponding icon. The theme follows the system color scheme until the user explicitly switches it for the current page. Collapsing controls hides only the right sidebar and lets the stage fill the available workspace; it must not break the full-width animation panel. The controls resize boundary may reduce the stage to 160px on desktop so measured-width action docking can engage. The camera action toggles camera mode without changing the avatar pose, position, scale, or face parameters. Only camera mode shows the bounded backdrop and replaces save with the export menu in the top-right action row; its backdrop color and square, rounded-square, or circular frame shape are configured in the Style panel and persist in the URL. The editing surface must allow rotated, scaled, or translated geometry to render beyond the nominal SVG viewport without clipping; camera mode alone owns clipping to the captured frame. Keep every camera frame shape at the same dimensions as the editing canvas and vertically center that canvas using symmetric stage padding; bottom interaction actions are absolute overlays and must not reserve extra layout space that pushes the avatar upward. Entering or leaving camera mode, changing the frame shape, or opening Animation must never shift the avatar geometry.

The stage's top-right save action captures a raster thumbnail of the current interactive SVG and stores the complete URL-backed avatar configuration as a local saved preset. The Build panel owns the saved-preset history at its top; each item is a 48px avatar thumbnail without a card surface, timestamp, or metadata chrome, its hit area and selected border follow that preset's own square, rounded, or circular camera-frame geometry, and selection is communicated only by that border. Selecting a thumbnail restores the complete body, face, view, palette, camera, lighting, shadow, interaction, and export state in one action. Keep saved presets browser-local, capped to a compact horizontal history, and resilient to malformed or obsolete local data. Saving or selecting a preset must not introduce a second configuration source: restored values continue through the normal state and URL synchronization path.

When the editor is closed, the stage's bottom-left Animation action precedes the mouse drag controls and opens a bottom timeline panel that spans the complete workspace beneath both the avatar stage and the controls sidebar; the panel must not be positioned inside or sized from the stage column alone. When the panel opens, that Animation action moves to the panel header, the mouse drag controls close the vacated gap at the stage's bottom-left, and the explicit icon-labeled Create and Playback tabs begin after a small horizontal gap from the action without repeating an additional Animation title. Once an animation source is selected, replace the generic Create label with a compact `Editing {animation name}` label while keeping the tab's edit-timeline behavior. Once the panel's measured height exceeds 40vh, move the mouse drag controls into that same header immediately before the tabs; its docked variant must match the tabs' 34px total height, while the stage variant retains its larger touch target. Return the controls to the stage when the panel drops back to 40vh or less or closes. The header tabs and the Once / Loop playback selector use the same padded outer group and inset rounded selected state as the stage's mouse-drag selector. The header keeps the global play / stop plus Create-only save icon actions pinned to the far right; do not duplicate those actions inside the settings card. On desktop, the panel's top edge is a height-resize boundary and may grow until only a compact 96px stage strip remains; its Playback library wraps into additional rows and scrolls vertically rather than creating a horizontal strip. Keep preview tiles at a stable size, distribute each row's remaining gap between items, and align the first and last tile to the content edges instead of leaving a residual empty block on the right. A keyframe's visual state records only whole-object X/Y position, yaw/pitch orientation, and the complete geometric face expression; its transition metadata records the duration and easing used to enter that frame, and it also captures a 48px transparent raster avatar thumbnail without the camera background or camera-frame crop. Keyframe selection uses one fixed rounded border independent of the configured camera frame. The thumbnail is display metadata and must not become animation state. Each draft keyframe has an explicit delete action. Playback interpolates numeric transform and face values across keyframes while keeping discrete face types stable until their transition point. At every new playback start, re-anchor the complete timeline to the avatar's current X/Y position and yaw/pitch orientation by applying the first-frame transform delta to every frame; preserve movement internal to the animation instead of snapping back to the coordinates that were active when the animation was selected or recorded. Only an animation that explicitly opts into a future locked-transform contract may bypass this re-anchoring. Built-in frames may derive per-frame transition durations from normalized non-uniform timing offsets so long holds, quick blinks, rebounds, and return poses do not collapse into equal-duration steps; each destination frame owns the duration and easing used to enter it. The Playback tab is one animation library: do not separate built-in presets and locally saved animations into different labeled groups or card treatments. Every library item directly renders a live avatar using the current body, palette, lighting, and shadow appearance; do not show a duration or separate text area, and overlay only the animation name at the preview's bottom-right. Selecting any library item stays in Playback, replaces the shared editor draft after confirmation only when that existing draft contains user-authored or saved content, opens the right-side animation tool panel with the selected frames, and immediately loops the animation. The selected source being built-in or saved does not affect replacement confirmation. The right-side tool panel has two explicit contexts: with no selected frame it edits animation-group name, position strategy, first frame, and once / loop behavior; with a selected frame it edits only that frame's incoming duration and easing. In loop playback the first frame's timing controls the last-to-first transition, while once playback shows its chosen first frame immediately. The built-in library covers subtle idle, blink, listening, nod, thinking, searching, working, happy, curious, surprised, bored, sad, laughing, playful, excited, and celebrate behaviors; each resolves relative to the current view and face, then loads into the same editable timeline without changing body shape, palette, camera, lighting, or shadow. Preset durations must preserve readable holds and transitions; avoid globally compressed playback that makes every expression feel abrupt. Every built-in or selected saved frame must be rendered offscreen through the same interactive avatar and transparent screenshot pipeline and backfilled with its own distinct thumbnail; do not leave frames as numbered fallbacks, duplicate one current-stage image across the sequence, or reuse camera-mode screenshots. Saved animations remain browser-local, can be loaded back into the shared timeline, and expose an explicit delete action with an in-panel confirmation; built-in presets are not deletable. Replacement confirmation must also render inside the panel rather than relying on a native browser dialog. Manual transform or face editing stops active playback. Do not introduce model-part binding or skeletal control until a concrete model contract exists.

The controls sidebar and full-width Animation panel are desktop work surfaces, not opaque page partitions. Render both as translucent frosted-glass panels with a thin boundary, backdrop blur, and sufficient text/control contrast in both themes. The controls sidebar exposes a draggable left boundary for width adjustment, while the Animation panel exposes a draggable top boundary for height adjustment; both handles support keyboard arrows and reset on double click. Keep these resize affordances hidden in the single-column narrow-screen layout.

The controls sidebar uses a four-way segmented button tab group for Build, Body, Style, and Effects. Keep the icons and accessible tab semantics, but use bounded button surfaces and a filled selected state instead of underline-only navigation.

The app repository triggers this Pages deployment only when `assets/avatar/**` or `packages/avatar/**` changes. Do not broaden the trigger to all `packages/**`.
